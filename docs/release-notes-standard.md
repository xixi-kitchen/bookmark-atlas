# 版本介绍编写与发布规范

每个正式版本都必须有自己的完整版本介绍，包括大版本、次版本和补丁版本。教学是附加层：介绍说明「更新了什么、对我有什么用、在哪里使用、需要注意什么」，教学带用户操作真实入口。不能因为某版没有教学就省略介绍，也不能用当前版本内容填充未知旧版本。

## 内容来源与呈现

应用内版本介绍的单一条目源是 `src/onboarding/releaseNotes.json`；`releaseCatalog.ts` 按版本精确查找，并按版本日期、语义版本倒序提供历史。`getReleaseNotes(version)` 查不到时返回 `undefined`，界面应说明该版介绍未收录，并提供正式历史入口。不得借用其他版本说明。

每个条目至少包含以下内容，全部面向用户提供 English 与简体中文：

| 字段 | 编写要求 |
| --- | --- |
| `version`、`date` | 唯一的稳定语义版本号；从 v0.9.6 起 `date` 为正式包冻结日期 `YYYY-MM-DD`，不代表商店通过或实际上架，不拿草稿或提交日期冒充渠道事件 |
| `title`、`summary` | 简洁标题和总体收益，说明本版解决的事情，不写宣传空话 |
| `sections` | 按 `added`、`changed`、`fixed`、`security`、`deprecated`、`removed` 分类；每类最多一次，空类不展示 |
| `sections[].items[]` | 每项有 `title` 与 `description`，说明具体变化及用户收益；可操作功能用 `where` 给出真实具体入口，后台修复可写自动生效的场景 |
| `gettingStarted` | 非空的上手步骤，按真实操作顺序写，不能只有「去试试」 |
| `notices` | 非空的迁移、费用、权限、数据或兼容注意事项；没有迁移操作时可如实说明，不编造保证 |
| `education` | 明确给出 `level` 与 `chapters`，决定本版是否额外邀请教学 |

本结构参考 [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/) 的逐版记录、日期与变更分类，以及 [Linear Changelog](https://linear.app/changelog) 的用户收益、功能解释与入口说明。本项目存在商店审核周期，采用下述包日期与渠道日期分离规则。编写时从已交付功能和缺陷修复归纳，不直接把 git log 当用户说明。空分类不凑数；安全项只写经过证据支持的实际改动，不承诺绝对安全。

## 介绍与教学的关系

- 每个大小版本都保留版本介绍入口；七天未读红点到期只清除提示状态，不能删除介绍或让入口失效。
- 普通小版本默认 `education.level: "notes"`，可展示轻量未读提示和版本介绍，不自动弹出大教学窗口。
- 重要的新功能或大改版在明确判断需要教学时使用 `"feature-tour"`，并列出非空、合法且不重复的教学章节。版本介绍仍须独立存在，不能被「开始教学／以后再说」替代。
- `chapters` 只允许 `basics`、`capture`、`ai`。`notes` 可以带章节以支持相关功能提示，但不能因此升级成自动教学；SemVer 数字本身不能自动决定教学强度。
- 未读状态、某个功能是否用过、教学进度分别记录；读完介绍不等于完成教学，跳过教学也不应使介绍消失。

## 稳定版本与历史资料

只把本版正式包包含、已验证的功能写入该版本；Driver.js 教学改造属于 v0.9.6，不能回写为 v0.9.5 的已发布功能。候选正式包的介绍不代表商店批准，公开渠道状态需单独说明。后续发布必须新增自己的条目，不覆盖旧版或沿用旧版正文。

当前目录收录 v0.9.6 与有充分资料的 v0.9.5；更早版本尚未按本结构整理时返回未收录，不借用其他版本。保留历史 v0.9.5 条目及文档：其正式商店/Release 发布日期经核对为 **2026-10-20**，内容依据 `docs/releases/v0.9.5.md` 与 `CHANGELOG.md`；后者标题的 2026-10-19 是较早的记录日期，不据此改写历史发布资料。

## 正式包日期与渠道日期

从 v0.9.6 起，JSON `date`、CHANGELOG 版本标题与包内发布说明的版本日期统一记录**正式包冻结日期**。v0.9.6 为 **2026-10-21**。它标识此次版本内容及不可变发布产物，不声称 Google 已审核通过。

Chrome 提交时间、审核状态、批准时间和实际上架时间属于独立的公开渠道状态；只有观察到相应事件后才能记录，不预填批准日期，不把上传成功或提交审核写成已发布。官网、下载与 GitHub 状态需区分当前稳定商店版和待审核候选版。

冻结后保留 ZIP 与 SHA-256。即使审核跨天，也不只为更新日期而重建 ZIP；批准或实际上架后更新渠道状态即可。若冻结后仍修改代码或包内容，须重新验证、冻结并记录对应产物与日期，不能把不同字节当成同一已提交包。

v0.9.5 需保留以下边界：已有画布不重置、无需重新导入；AI 需自配接口、模型和 Key，并适用服务商费用与政策；已保存 AI 配置及凭据只留本机，不进入同步、共享或扩展备份；图片及二进制附件仍不跨设备同步。不要扩大为「所有数据都已跨设备同步」、系统钥匙串、绝对安全、已正式支持 Edge/Safari 等未被证实的结论。

## 每次发布的检查

1. 核对正式版本、正式包冻结日期和包内交付范围，新增双语 JSON 条目；记录功能入口、上手步骤与注意事项。渠道审核及上架状态另行据实记录。
2. 明确选择 `notes` 或 `feature-tour`；重要教学应指向真实操作，介绍本身始终可查看。
3. 按既有流程维护 `CHANGELOG.md`、`docs/releases/v<version>.md`、包版本和构建结果，避免不同载体的事实相互矛盾。
4. 运行 `npm run verify:release`；该命令保留原有发布文档及构建版本检查，并通过 `scripts/lib/validate-release-notes.mjs` 检查 JSON：当前包版本存在、版本唯一且为稳定 SemVer、真实 ISO 日期、所有必填中英字段非空、分类合法且不重复、上手步骤及注意事项非空、教学级别与章节有效。缺失新版条目必须阻止发布，不能静默回退。
5. 运行 `npm run check`，再核对中英界面能查看当前版本介绍、未知版本不会展示其他版本正文、小版本不自动弹出大教学、教学与介绍入口同时存在。自动校验只证明结构与程序契约，不代替发布者核实内容、日期、费用和兼容事实。
